# Метаданные учебного датасета «Lending Club Loan Data 2007–2018»

## 1. Назначение

Датасет предназначен для обучения полному аналитическому циклу в задаче кредитного скоринга: постановке бизнес-вопроса, проверке качества данных, приведению таблицы к консистентной форме, расчёту KPI, разведочному анализу, проверке гипотез о предикторах дефолта, интерпретации результатов и подготовке рекомендаций.

Данные являются публичными и получены с платформы Kaggle. Набор содержит исторические сведения о кредитах, выданных американской P2P-платформой Lending Club. Персональные идентификаторы заёмщиков (`id`, `member_id`, `url`) обезличены и в исходном файле содержат 100% пропусков.

## 3. Как понимать единицу наблюдения

Одна строка — один выданный кредит. В отличие от товарных позиций в чеке, здесь каждая строка уникальна и не требует группировки для расчёта ключевых показателей.

Важно учитывать, что в исходном наборе присутствуют кредиты с разными статусами (`loan_status`). Для задачи бинарной классификации оставлены только завершённые кредиты:
- `Fully Paid` — полностью погашен (целевой класс 0);
- `Charged Off` — списан как безнадёжный (целевой класс 1).

Статус `Current` и прочие незавершённые состояния исключены, поскольку итог кредитования по ним ещё не определён.

## 5. Связи и бизнес-правила

- `funded_amnt` ≤ `loan_amnt`.
- `funded_amnt_inv` ≤ `funded_amnt`.
- `installment` рассчитывается по аннуитетной формуле от `loan_amnt`, `int_rate`, `term`.
- `grade` и `sub_grade` согласованы: подрейтинг начинается с буквы grade.
- `dti` в корректных наблюдениях должен лежать в диапазоне 0–100%; значения −1,00 и 999,00 — аномалии.
- `annual_inc` = 0 означает либо отсутствие дохода, либо отказ указывать — требует проверки.
- Целевая переменная `target_default` = 1 только для статуса `Charged Off`; для `Fully Paid` = 0.

## 6. Категориальные справочники после стандартизации

- **Рейтинги (`grade`)**: A, B, C, D, E, F, G — от лучшего к худшему.
- **Подрейтинги (`sub_grade`)**: A1…G5 (35 уровней).
- **Сроки (`term`)**: 36 months, 60 months.
- **Тип жилья (`home_ownership`)**: MORTGAGE, RENT, OWN, OTHER, ANY.
- **Цель кредита (`purpose`)**: debt_consolidation, credit_card, home_improvement, major_purchase, medical, small_business, car, vacation, moving, house, renewable_energy, educational, wedding, other.
- **Статус проверки (`verification_status`)**: Verified, Source Verified, Not Verified.
- **Тип заявки (`application_type`)**: Individual, Joint App.

## 7. Намеренные и естественные проблемы качества

Проблемы присутствуют в исходном файле и требуют обработки в ноутбуке.

| Проблема | Масштаб | Рекомендуемая обработка |
|---|---|---|
| 100% пропусков в `id`, `member_id`, `url` | 2 260 668 × 3 | Удалить столбцы |
| >80% пропусков в `hardship_*`, `settlement_*`, `sec_app_*`, `joint_*`, `desc` | 39 столбцов | Удалить столбцы |
| Пропуски >50% в `mths_since_*` | 5 столбцов | Удалить столбцы |
| Оставшиеся пропуски в числовых полях | небольшой % | Заполнить медианой |
| Оставшиеся пропуски в категориальных полях | небольшой % | Заполнить модой |
| Аномальные значения `dti` | мин. −1,00%, макс. 999,00% | Исключить или ограничить |
| Правосторонний скос `annual_inc` | максимум > $10 млн | Использовать медиану, а не среднее |
| Бесконечные значения в новых признаках | `inf` из-за деления на 0 | Заменить на `NaN`, заполнить медианой |
| Незавершённые кредиты (`Current`, `Late`) | ~42% строк | Исключить из бинарной классификации |

## 11. Ограничения интерпретации

- Данные исторические (2007–2018) и могут не отражать текущие тренды кредитного рынка.
- Пропуски во вторичных компонентах (`hardship_*`, `settlement_*`) ограничивают полноту их анализа.
- Идентификаторы заёмщиков обезличены — нельзя отследить повторные займы одного клиента.
- Временная ось представлена только годом выдачи — квартальная и месячная динамика недоступна.
- Правосторонний скос распределений делает средние значения нерепрезентативными — используются медианы.
- Наблюдаемые корреляции не доказывают причинно-следственных связей.
- Модели ML на этих данных нуждаются в балансировке классов (соотношение 4:1).

## 12. Рекомендуемый порядок работы студента

1. Прочитать паспорт и определить grain таблицы.
2. Загрузить исходный CSV без ручного редактирования файла.
3. Измерить пропуски, дубли, типы и нарушения бизнес-правил.
4. Удалить столбцы с критическими пропусками (>80%).
5. Отфильтровать завершённые кредиты (Fully Paid, Charged Off).
6. Выполнить импутацию пропусков (медиана/мода).
7. Создать производные признаки (Feature Engineering).
8. Выполнить разведочный анализ: распределения, категории, корреляции.
9. Построить матрицу «Grade × Term» и проверить гипотезы.
10. Отделить наблюдения от интерпретаций — не называть корреляцию причиной.
11. Сформулировать ограничения и рекомендации.
12. Собрать дашборд в BI-инструменте.

## 13. Воспроизводимость

Основной способ воспроизведения — открыть `Код.ipynb`, установить зависимости и выполнить все ячейки сверху вниз. Ноутбук самостоятельно читает исходный CSV, создаёт очищенный файл, выполняет программные проверки и сохраняет итоговый дашборд.

Контроль целостности можно выполнять сравнением SHA-256 из этого документа с фактической контрольной суммой файла.
